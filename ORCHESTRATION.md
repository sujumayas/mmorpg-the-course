# Orchestration: Writing 39 Courses with Subagents

The full program is 39 courses × 14 lectures ≈ 546 lectures, plus 72 signature interactives, labs and exam banks. That's far beyond one conversation. This file is the run plan for Claude Code (or Claude Cowork), which can spawn parallel subagents defined in `.claude/agents/`.

## 1. Setup

```bash
git init && git add -A && git commit -m "Curriculum architecture + exemplar"
pip install pyyaml playwright && playwright install chromium
python tools/build_plan.py      # regenerates PLAN.md status + syllabus links
```

Subagents in this repo:

| Agent | Job | Unit of work |
|---|---|---|
| `course-author` | Lectures, labs, interactive specs | 2–3 weeks of one course |
| `example-builder` | Self-contained interactive HTML | One worked example |
| `course-reviewer` | QA, recompute numbers, verify facts, fix | One course |

Why 2–3 weeks per author task: a lecture is 2,500–5,000 words plus research, so a full 14-week course in one subagent would exhaust its context and lose quality in later weeks.

## 2. Waves (priority order)

Build in dependency order so later courses can link back to earlier ones instead of re-teaching. If usage runs out mid-plan, earlier waves are the most valuable to have finished.

| Wave | Courses | Why first |
|---|---|---|
| 1 · The balance spine | MA101, MA102, GD203, MMO303 | The math → combat → class-balance thread; the exemplar lives here |
| 2 · Systems and economy | GD101, GD102, MMO304, MMO401 | Faucets/sinks spiral from year 1 to year 4 |
| 3 · Worlds and society | GS101, UX201, MMO301, MMO305, MMO402 | The social-science core of the specialization |
| 4 · Technology | CS101, CS102, CS202, DB201, MMO302, MMO309, MMO404 | Networking and server thread |
| 5 · Content and operations | GD201, GD202, CS203, MMO306, MMO307, MMO308, MMO407 | |
| 6 · Remaining core | AR101, AU101, CS201, MA201, PR101, MMO403, MMO405, MMO406 | |
| 7 · Studio courses | PR201, PR301, PR401, PR402 | Mostly briefs, milestones and rubrics |

Within a wave, run courses in parallel (one author subagent per 2–3 weeks), then builders for that wave's interactive specs, then one reviewer per course.

## 3. Kickoff prompt (paste into Claude Code at the repo root)

```text
/goal Complete wave 1 of ORCHESTRATION.md, then continue wave by wave until I stop you or usage runs out.

For each course in the current wave:
1. Spawn course-author subagents in parallel, each assigned 2-3 weeks of the course (weeks 1-14).
   Tell each one the course code, its weeks, and that the MMO303 w02 exemplar defines "done".
2. When a course's lectures are written, spawn example-builder subagents in parallel, one per
   "## Interactive spec" section, prioritizing the signature worked examples in curriculum.yaml.
3. Spawn one course-reviewer for the course. Apply its fixes.
4. Write assessments/: assignment briefs + rubrics, and an exam bank of >=40 questions with answers.
5. Run python tools/build_plan.py, commit with message "<CODE>: complete", and move on.

Never skip verification of real-game facts. Keep a running log in docs/BUILD_LOG.md: courses done,
unverified facts, open questions for me. Pause and ask me only if a design decision in
docs/00-course-architecture-research.md §5 blocks progress.
```

## 4. QA checklist (used by `course-reviewer`)

1. Lecture follows the template sections in `STYLE_GUIDE.md` §2, 2,500–5,000 words.
2. Every worked example meets all 7 steps (hook, model, numbers, visual, cross-game, judgment, check-yourself).
3. Every number in every table recomputes correctly.
4. Every real-game fact is cited with version/era; no `(verify)` items remain unresolved.
5. No quote longer than a short phrase; no copyrighted art or characters in interactives.
6. Concepts used are taught earlier (in prerequisites or this lecture); prerequisite lectures are linked.
7. Interactive: no console errors, correct at 390px and desktop, keyboard reachable, dark mode legible, numbers match the lecture.
8. Check-yourself answers are correct and require using the model.
9. Syllabus schedule links resolve (run `tools/build_plan.py`).
10. Tone: second person, plain language, jargon defined on first use.

## 5. Tracking

`PLAN.md` → "Build status" shows lectures and examples per course. It is regenerated by `tools/build_plan.py`; never edit it by hand.
