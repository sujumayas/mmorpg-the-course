1,800 bytes replay 30 seconds, if every input is in them

The replay re-runs the recorded commands through the same step function. With every input recorded it matches the live run to the last bit. Switch off one input and watch which part of the state breaks, and that the error never shrinks back.

Replay uses: MATCH

Arrow keys or WASD to move, Space to fire. Input is sampled once per tick, 60 times a second.

Simulation: 60 ticks per second, 1,800 ticks. Buttons are one byte per tick (UP 1, DOWN 2, LEFT 4, RIGHT 8, FIRE 16). step moves 90 units per second and rolls a 25% hit per shot from a mulberry32 generator seeded with the world seed. The sparkle on hits uses its own generator, so drawing never consumes simulation numbers. Timestep off: dt = (1/60) × (0.8 + 0.4v), v from mulberry32 seed 5. Seeded RNG off: the replay seeds with 999. Record every input off: FIRE is dropped on ticks where tick % 7 = 0.

The scripted player holds RIGHT, then UP, then LEFT for 600 ticks each and fires every 10th tick, the same player as the lecture's table. End position, shots, change count and sizes match that table. The score and the jitter drift differ, because this page rolls hits and jitter with mulberry32 while the lecture's Python uses random.Random. Checksum packs x and y as little-endian float64 and score and shots as int32, then hashes the 24 bytes with 32-bit FNV-1a. Doom demo layout from the 1997 id Software source release: 13-byte header, 4 bytes per player per tic at 35 tics per second, 1-byte end marker.
