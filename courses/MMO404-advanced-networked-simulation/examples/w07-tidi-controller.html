A controller that pays back its debt

A node hosts a battle. Each real second it measures the cost of one game-second, tracks the CPU work it still owes (the backlog, which players feel as lag), and picks the next second's game speed.

The first second always overruns. How long the lag lives is your choice.

Model constants. work(n) = 0.0003 n + 0.000001 n² and C = 1 are MMO302 week 12's teaching node, not measured EVE numbers. The battle timeline and wave sizes are invented. The 10% floor is EVE Online's. Noise uses the lecture's seeded mulberry32 generator.

Model from MMO404 week 7, sections 2 and 3. Each real second: m = work(n)(1 + noise(2r − 1)); q (the backlog) = max(0, q + f m − C); target = clamp((aim × C − q/τ) / m, floor, 1); f += α(target − f), with α_down when the target is below f. f and q are recorded before the control update, as in the lecture's code.
