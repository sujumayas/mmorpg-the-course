How wide should the seam be?

With a sharp border, players standing near the line change server many times a second. A band a few metres wide stops most of that. Past the distance players wander, a wider band only adds ghosts, so the seam's cost curve is a U with a flat bottom.

—band width w
—handoffs per second H
—ghosts G(w)
—seam cost S
—handoff CPU
—ghost CPU
—handoffs per hour
—cheapest band

Model: G(w) = 2ρL(R + w) with ρ = 0.002 per m² and L = 500 m. S(w) = H(w)·Eh + G(w)·10·0.003 ms per second. H(w) comes from the lecture's simulation: 100 travellers at ±5 m/s, 300 dwellers pulled back to a fixed spot with spread σ, dt = 0.1 s, seeded PRNG (mulberry32). The cost curve averages 8 seeds because a single run at w = 0 depends on how many dwellers happen to stand near the line (the Python reference ranges from 6.2 to 10.9 handoffs per second across seeds 1 to 8). The live map runs one seed. The constants are teaching values, so expect H to differ from the lecture table by a few percent.
