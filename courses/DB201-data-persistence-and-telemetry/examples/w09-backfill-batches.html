DB201 Data Persistence and Telemetry · Week 9 · Worked example

Batch size sets the stall. Duty cycle sets the total.

A batched backfill of 60 million rows. Shrink the batches from 100,000 rows to 1,000 and the longest wait a player sees falls 100 times, from 5 s to 50 ms. The whole job takes 10% longer.

–batches, N/b
–longest stall, b/r
–each batch runs, b/r + o
–running time, (N/b)(b/r + o)
–total time, running / d
–total in hours
–floor, N/(r·d)
–overhead share of running time
–longest wait on the timeline
–recommended b = r × stall budget
–minimum d = N / (r × time budget)

One statement sets b = N and d = 1.

Model from DB201 week 9: batches = N/b, longest stall = b/r, total = (N/b)(b/r + o)/d = N/(r·d) + N·o/(b·d). When b does not divide N, the last batch is smaller and batches round up. The timeline uses a fixed seed, so a write “hits” the batch with the chance you set (default 1, the worst case). Shapes are generic; no game art.
