CS201 Game Engine Architecture · Week 12 · Worked example

A save from version 1 still opens at version 20

Each release adds one small migration to a chain. Old saves walk the chain one step at a time. Direct converters would need a rewrite of every old one at every release.

Load walks the save along the chain, 600 ms per step.

Tagged fields

With tags, a patch that only adds a field with a default needs no migration. Renames, unit changes and restructures still do.

Migrations from lecture section 2: v1→v2 renames hp to health, v2→v3 turns tile pos into pixels at 16 px per tile, v3→v4 moves gold into a wallet with gems: 0. Later versions are "patch k" stand-ins that only bump the version. Cost model: a chain writes one function per release (N − 1 in total); direct converters must write k − 1 new ones at release k (N(N − 1)/2 in total). When N > 8 the chain shows the four built-in versions, a gap box for the middle patches (one animation step), and the last four versions.
